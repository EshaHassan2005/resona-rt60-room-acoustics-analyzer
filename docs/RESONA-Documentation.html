1 — Overview

RESONA turns a single recorded hand clap — or just a room's dimensions — into a full acoustic diagnostic report. It measures how long sound lingers in a room (RT60), which frequencies are misbehaving, where standing waves (room modes) will cause boomy bass, and it recommends how much acoustic panel material is needed to fix it — using the same ISO 3382-1 signal-processing standard that professional acoustic analyzers use, running in a browser.

1.1 Problem

Every room "colors" the sound inside it. Sound bounces off walls, ceilings, and furniture, arriving at the ear many times at many delays — this pileup is reverberation. Two identical speakers in two different rooms can sound completely different purely because of room geometry and surface materials.

This has real consequences beyond audiophile concerns:

  • Classrooms: excess reverberation directly hurts speech intelligibility and, by extension, learning (codified into law via ANSI/ASA S12.60, the US school acoustics design standard).
  • Recording studios: unwanted "room color" and flutter echo degrade recordings.
  • Concert halls: the "right" amount of reverb differs for speech vs. orchestral music vs. opera.
  • Offices: poor acoustics reduce speech privacy and cause listening fatigue.

Measuring and fixing this has historically required either expensive calibrated hardware or guesswork. RESONA provides a free, accessible way to measure a room and get a quantitative, materials-based treatment plan.

1.2 Solution

RESONA takes a recorded impulsive sound (a clap, balloon pop) — or, alternatively, just the room's dimensions — and runs it through the same digital signal processing (DSP) pipeline that professional acoustic measurement software uses, reimplemented in Python and served through a web app that needs no special hardware beyond a laptop microphone.

2 — Architecture

  • Frontend: collects audio (file upload OR live mic recording via the browser's MediaRecorder API) and/or room dimensions, and renders results as charts, tables, a 3D waterfall plot, and a printable report.
  • Backend: completely stateless. Every request re-decodes the uploaded audio from scratch and runs the DSP pipeline fresh. Nothing is saved server-side — no database. "Saved reports" in the UI live entirely in the browser's localStorage.

3 — Core Pipeline

Nearly every feature in RESONA depends on the same five steps, run in order:

1. RECORD/UPLOAD a clap │ 2. ONSET DETECTION → find_onset() "Where does the clap actually start?" │ 3. TRIM → extract_impulse_response() "Cut away everything before the clap" │ 4. ENERGY DECAY CURVE → energy_decay() → lundeby_correction() │ "Turn the messy waveform into a clean dB-vs-time decay curve" │ 5. RT60 ESTIMATION → estimate_rt60() "Fit a line to the decay curve, extrapolate to -60 dB" │ ▼ Everything else (octave bands, room modes, waterfall, clarity, treatment) is this same chain, either applied broadband or repeated per frequency band.

4 — Backend

4.1 audio_utils.py — getting audio into a usable form

load_audio(file_storage, target_sr=None)

The entry point every route calls first:

  1. Checks file size (rejects anything over MAX_FILE_SIZE_MB = 50).
  2. Reads the raw bytes.
  3. Tries to decode with Librosa (librosa.load), which handles WAV/MP3/FLAC/OGG directly.
  4. If that fails, falls back to _convert_with_ffmpeg() — needed for live mic recordings: browsers record audio as audio/webm;codecs=opus (Chrome/Firefox default), and Librosa's normal decoder can't always read that container reliably in every environment. ffmpeg converts it to a clean 44.1kHz mono WAV file first.
  5. Converts everything to a float64 NumPy array + integer sample rate, and raises a clean AudioLoadError for anything that still fails (empty audio, corrupt file, etc.) so the Flask routes can return a proper 400 error instead of crashing.

_convert_with_ffmpeg(raw_bytes)

Writes the raw bytes to a temp file, shells out to ffmpeg (located via the imageio_ffmpeg package so no system-level ffmpeg install is required), converts to WAV, and returns the path. Cleans up temp files in a finally block either way.

downsample_for_preview(signal, sample_rate, target_points=2000)

The raw waveform of even a 2-second clap at 44.1kHz is ~88,000 samples — too many points to usefully draw as an SVG line in the browser. This function buckets the signal into target_points buckets and, in each bucket, keeps the peak sample (not the average), since averaging would smear out transient spikes and make the waveform preview look flatter/quieter than it really is. This is a UI convenience function only — it does not feed into any acoustic calculation, only the waveform picture shown to the user.

4.2 dsp.py — the acoustic math engine

Onset detection

find_onset(signal, sample_rate, threshold_db=20.0, frame_ms=5.0, sustain_ms=50.0, sustain_margin_db=6.0)

Answers: where in this recording does the clap begin? This has to be precise because every downstream calculation (decay curve, RT60, clarity windows) is timed relative to this point.

  1. Chops the signal into 5 ms frames.
  2. For each frame, computes both peak amplitude (dB) and RMS amplitude (dB).
  3. Estimates the noise floor as the median RMS level across all frames — median is used (not mean) because it's robust to the one loud clap frame skewing the estimate.
  4. Candidate onset frames = frames whose peak exceeds noise_floor + threshold_db (default: 20 dB above the floor).
  5. Sustain check: a candidate frame is only accepted as the real clap if the following ~50 ms also stays elevated above the noise floor. This rejects short transient spikes — a cough, a chair scrape, a door slam — that are loud but have no decaying reverb tail after them. Only a genuine clap-like event (loud + followed by decay) passes.
  6. Within the accepted frame, the exact sample-level onset is refined by walking backward from the local peak until the signal drops below a rise threshold.

_global_peak_onset(signal, threshold_db=20.0)

A "naive" fallback strategy: finds the loudest sample and treats that as the clap. Kept only for very short signals where there aren't enough frames (n_frames < 6) for the frame-based statistics above to be meaningful. This is the version that would be fooled by a loud noise burst with no decay tail — which is why the sustain-checked find_onset() exists as the default (covered by the regression test test_find_onset_ignores_louder_stray_noise_before_clap).

extract_impulse_response(signal, sample_rate, threshold_db=20.0)

Calls find_onset() then slices the signal from that point onward: signal[onset_idx:]. This trimmed signal is treated as an approximation of the room's impulse response for every downstream calculation.

Energy decay curve — Schroeder integration + Lundeby correction

Real recordings are too noisy and jagged to read a decay rate directly off the raw waveform envelope. In 1965, Manfred Schroeder proved that taking the impulse response's squared amplitude (energy) and integrating it backward — from the end of the recording toward the start — produces a smooth, statistically correct decay curve, since at each moment it represents the total remaining acoustic energy, which is exactly what "decay" physically means.

EDC(t) = ∫ from t to ∞ of h²(τ) dτ (Schroeder backward integral) decay_dB(t) = 10 · log10( EDC(t) / EDC(0) ) (normalized, converted to dB)

_raw_schroeder(energy, dt)

The literal implementation of the formula above: reverses the energy array, runs scipy.integrate.cumulative_trapezoid (a running/cumulative integral), reverses the result back, normalizes to the peak (so it starts at 0 dB), clips tiny values to avoid log(0), and converts to dB.

Raw Schroeder integration has a known limitation: real recordings never decay to true silence — there is always a background noise floor. Since the integral sums all remaining energy including that noise, the tail of the curve flattens and bends upward instead of continuing to fall. This biases any RT60 estimate that touches the late part of the curve, making the room appear more reverberant than it actually is.

lundeby_correction(impulse_response, sampling_rate) — the most significant function in the codebase.

The ISO 3382-1 standard method for handling noisy, real-world (non-anechoic-chamber) recordings:

  1. Splits the signal into 20 ms blocks, computes mean energy (dB) per block.
  2. Estimates an initial noise floor from the quietest 10% of blocks (the tail end).
  3. Fits a straight line (linear regression, scipy.stats.linregress) to the decay region between 5 dB below the peak and 10 dB above the estimated noise floor — i.e., only the "clean" part of the decay, avoiding both the very top (non-linear initial reflections) and the very bottom (noise).
  4. Uses that fitted line to predict the crossing point — the time at which the decay line would intersect the noise floor.
  5. Re-estimates the noise floor using only the blocks after that crossing point (a tighter, more localized estimate).
  6. Repeats steps 3–5 up to 5 times until the crossing point stabilizes (converges to within 5 ms).
  7. Subtracts the estimated noise-floor energy from the signal before doing the Schroeder integration, and analytically appends a "tail energy" term (from the fitted exponential decay beyond the crossing point) so the integral stays mathematically complete without being contaminated by measured noise.
  8. Returns (decay_db, t_cross, noise_floor_db).

If anything goes wrong (too few samples, fewer than 5 valid blocks, a bad regression), it falls back to _raw_schroeder().

energy_decay(impulse_response, sampling_rate, use_lundeby=True)

The public-facing wrapper every route calls. Tries lundeby_correction() first (wrapped in try/except so any failure silently falls back to _raw_schroeder()), so the caller always gets some usable decay curve.

Note: Lundeby's method is the most sophisticated algorithm in the codebase — it is the same technique used by professional acoustic measurement software, not a simplified approximation of it.

RT60 estimation

estimate_rt60(decay_db, time, db_start=-5.0, db_end=-25.0)

RT60 is the time for sound energy to decay by 60 dB. Real recordings rarely have 60 dB of clean dynamic range above the noise floor, so rather than measuring the full 60 dB drop directly, the standard approach measures a smaller, cleaner segment and extrapolates:

T20 (db_start=-5, db_end=-25): measure the slope across a 20 dB span, then scale to 60 dB T30 (db_start=-5, db_end=-35): measure the slope across a 30 dB span, then scale to 60 dB RT60 = -60 / slope (slope is in dB/second, from linear regression)

Finds the array indices closest to db_start and db_end, runs scipy.stats.linregress on that slice of the decay curve, and returns the RT60 seconds, the raw slope, intercept, and R² (r_squared) — the goodness-of-fit. A low R² indicates the decay wasn't cleanly linear over that range, usually meaning a bad recording or an unusual room. Raises ValueError if the fit isn't valid (e.g., a flat or increasing curve, or the requested dB range isn't spanned).

app.py calls this twice per analysis — once for T20, once for T30 — and returns both plus their R² values so reliability can be judged.

Extrapolation is used instead of measuring the real 60 dB drop because background/electrical noise in a typical consumer mic recording sits well above where a true 60-dB-down signal would be. Extrapolating from a cleaner, higher-SNR portion of the decay (which is empirically linear in a diffuse sound field) avoids needing an impossibly quiet room.

Octave-band filtering

Reverberation time is not one single value for a room — bass and treble typically decay at very different rates depending on materials (soft furnishings absorb highs well but do almost nothing for bass). RT60 is therefore standardly reported per octave band.

octave_band(impulse_response, sample_rate, center_freq)

For a given center frequency, computes the band edges as fl = center/√2 and fh = center·√2, then calls bandpass().

bandpass(data, edges, sample_rate, poles=5)

Designs a 5th-order Butterworth bandpass filter (scipy.signal.butter, output as second-order sections — sos — for numerical stability) and applies it with scipy.signal.sosfiltfilt — zero-phase filtering: the filter runs forward, then backward, cancelling the phase delay/distortion a normal one-directional filter would introduce. This matters because a phase-shifted filter would smear the clap's sharp onset in time, corrupting every downstream timing-dependent measurement (onset detection, decay-curve timing). The tradeoff: sosfiltfilt needs the whole signal at once (non-causal), which is fine for offline analysis but would not work in a real-time system.

Validates that the requested band edges are within (0, Nyquist) — otherwise raises ValueError.

all_octave_bands(impulse_response, sample_rate, bands=None)

Loops over the 6 standard bands — OCTAVE_BANDS = [125, 250, 500, 1000, 2000, 4000] Hz — and runs octave_band() on each, skipping any band whose upper edge would exceed the Nyquist frequency (half the sample rate), since content above Nyquist cannot physically be filtered for (e.g. a 4000 Hz band on an 8kHz sample rate is silently dropped rather than crashing).

FFT (frequency spectrum)

get_fft(signal, sample_rate)

A direct call to scipy.fft.fft + scipy.fft.fftfreq, returning (magnitude, frequencies). Because an FFT of a real-valued signal is symmetric, every caller takes only the first half of the array (amp[:half]) — the "negative frequency" mirror half is discarded as redundant. Used both for the raw /fft endpoint and internally by calculate_room_modes() to find actual resonant peaks.

Clarity & Definition metrics

clarity_index(impulse_response, sample_rate, time_ms)

Computes C50 or C80 depending on time_ms (50 or 80):

C = 10 · log10( E_early / E_late ) [dB]

Splits the squared impulse response's energy at the cutoff sample, sums "early" energy (before cutoff) and "late" energy (after), and takes the log ratio. Positive = clear/direct sound dominates; negative = reverberant/blurred sound dominates. Raises ValueError if there's no late-arriving energy (a degenerate/too-short recording).

definition_index(impulse_response, sample_rate, time_ms=50.0)

Computes D50 — the same early/late split, expressed as a percentage of total energy rather than a log ratio:

D50 = (E_early / E_total) × 100 [%]

The 50 ms window used for speech (C50/D50) versus the 80 ms window for music (C80) matches human perception: energy arriving within ~50 ms of the direct sound is perceptually fused with it and reinforces clarity for speech, while energy after that is perceived as blur/echo. Music (with slower transients and a desirable sense of "warmth"/envelopment from later reflections) tolerates a longer early window before it's perceived as blur.

Bass/Treble Ratio (tonal balance)

bass_treble_ratio(rt60_by_band)

Standard architectural-acoustics tonal-balance metrics (Bradley 1986 / Beranek), computed from the actually-measured per-band RT60 values rather than estimated multipliers:

BR (Bass Ratio) = (RT60_125 + RT60_250) / (RT60_500 + RT60_1000) TR (Treble Ratio) = (RT60_2000 + RT60_4000) / (RT60_500 + RT60_1000)
  • BR > 1 → bass decays longer than mids → "warm"/bass-heavy room.
  • BR < 1 → bass decays faster than mids → "thin"/bass-light room.
  • A commonly cited healthy range is roughly 0.9–1.25 for general rooms (concert halls skew slightly higher, ~1.1–1.25).
  • TR < 1 is normal (highs absorbed faster than mids by furnishings/air); TR near/above 1 suggests an unusually bright/reflective room.

Requires the 125/250/500/1000 Hz bands to compute BR (raises ValueError if any is missing); the 2000/4000 Hz bands are optional — if missing, treble_ratio is returned as None rather than failing the whole calculation.

Room modes (standing waves)

Below a certain frequency, sound in a room doesn't behave as an even, diffuse field — it behaves as standing waves between parallel surfaces, at frequencies fixed by the room's exact dimensions. This is why bass can sound "boomy" in one corner and "thin" a meter away.

The Rayleigh equation for a rectangular room:

f(nx, ny, nz) = (c/2) · √[ (nx/L)² + (ny/W)² + (nz/H)² ]

where c = 343 m/s (speed of sound), L, W, H are room length/width/height, and nx, ny, nz are non-negative integers (not all zero) — the mode's "order" in each dimension.

calculate_room_modes(impulse_response, sample_rate, length_m=6.0, width_m=5.0, height_m=2.8, max_freq=300.0)

  1. Computes room volume = L × W × H.
  2. Runs the broadband decay/RT60 pipeline (falls back to a default 0.5 s if it fails) to get an RT60 value.
  3. Computes the Schroeder cutoff frequency: f_s = 2000 · √(RT60 / V).
  4. Loops over all integer combinations of (nx, ny, nz) up to bounds computed from max_freq, computing each mode's frequency via the Rayleigh equation, keeping only modes below both max_freq (300 Hz, a practical audible cutoff) and the Schroeder frequency (above f_s, individual modes aren't meaningfully separate anymore).
  5. Classifies each surviving mode by counting non-zero indices:
    • 1 non-zero → axial (reflects between 2 parallel walls — strongest, most audible, ~100% modal energy)
    • 2 non-zero → tangential (4 surfaces, ~50% energy)
    • 3 non-zero → oblique (all 6 surfaces, weakest, ~25% energy, decays fastest)
  6. Sorts modes by frequency.
  7. Runs get_fft() on the impulse response, restricts to the 20–300 Hz range, normalizes amplitude, and uses scipy.signal.find_peaks to find actual resonant peaks in the measured spectrum.
  8. Matches each measured peak to its nearest theoretical mode (only accepted if within 2.5 Hz) — turning the theoretical mode list into a set of modes confirmed to be physically present and audible in the actual room.

Returns a dict with schroeder_freq, rt60_seconds, the full modes list, the FFT curve, and matched_peaks.

3D Waterfall (Cumulative Spectral Decay)

A single RT60 number — even 6 per-band numbers — still hides information. A waterfall (CSD) plot shows the full time evolution of decay across frequency simultaneously: one axis is time, one is frequency, one is level (dB). This is the classic tool acousticians use to spot a frequency that "rings on" far longer than its neighbors, visible as an isolated ridge that doesn't die down with the rest.

calculate_waterfall(impulse_response, sample_rate, target_points=50)

  1. Runs all_octave_bands() to get the 6 filtered signals.
  2. Picks a common time grid: min(1.5 seconds, actual recording length), split into target_points (50) steps.
  3. For each band: computes its energy_decay(), then interpolates (np.interp) that band's decay curve onto the shared time grid (so all 6 bands can be compared point-for-point on the same axis) and clips to [-60, 0] dB.
  4. Returns the shared time axis plus a dict of {band_frequency: [decay values...]}.

This feeds directly into WaterfallPlot3D.jsx on the frontend, which renders it as an interactive, orbit-controllable 3D surface.

4.3 treatment.py

This module turns a measured RT60 into a concrete, materials-based treatment plan, using the classical Sabine equation (1898, Wallace Sabine):

RT60 = 0.161 · V / A ⟺ A = 0.161 · V / RT60

where V = room volume (m³) and A = total absorption in sabins (metric sabins = m² of a perfectly absorptive surface). The constant 0.161 comes from the speed of sound and SI unit conversions.

load_acoustic_targets() — loads and returns acoustic_targets.json (see §4.4) — the room-type RT60 targets and material absorption coefficients.

sabine_absorption(rt60_seconds, volume_m3)

Direct implementation of A = 0.161 · V / RT60. Confirmed by test: sabine_absorption(0.5, 100.0) == 0.161*100/0.5. Rejects non-positive RT60 or volume (ValueError) — physically, both must be positive. A longer RT60 (more "live" room) implies less absorption, which the tests explicitly confirm.

absorption_deficit(measured_rt60_seconds, target_rt60_seconds, volume_m3)

Computes how much more absorption a room needs to hit its target:

deficit = A_needed_for_target − A_currently_present
  • Positive deficit → room is too reverberant, needs more absorption.
  • Negative deficit → room already meets or beats the target.
  • Zero → exactly at target.

recommend_material_area(deficit_sabins, material, targets, center_freq)

Converts an absorption deficit (in sabins) into a physical area (m²) of a specific material:

area = deficit_sabins / absorption_coefficient(material, center_freq)
  • If the deficit is ≤ 0, returns 0.0 (no treatment needed).
  • A material with a higher absorption coefficient at that frequency needs less area to close the same deficit (e.g. acoustic_panel at 1000 Hz needs less area than at 125 Hz, because it's far less absorptive at 125 Hz — 0.15 vs. 0.90 — this is why bass is harder to treat than treble, and why dedicated bass traps exist).
  • Raises ValueError for an unknown material name or an unknown octave band.

recommend_treatment(measured_rt60_by_band, volume_m3, room_type, targets, material="acoustic_panel")

The end-to-end orchestrator called by the /treatment route: looks up the target RT60 for room_type, then for each measured octave band computes absorption_deficit() against that target and recommend_material_area() for the chosen material, returning a bands dict with one entry per band.

room_surface_area(length_m, width_m, height_m, volume_m3)

If full dimensions are available, computes the true surface area 2·(L·W + L·H + W·H). If only a bare volume was submitted, falls back to estimating a cube-shaped room of that volume — flagged in the return value as estimated: True.

compare_absorption_models(rt60, volume_m3, surface_area_m2)

Compares the Sabine-equation absorption estimate against an Eyring-equation estimate (RT60 = 0.161·V / (−S·ln(1−ᾱ))) for the same room — Eyring is generally considered more accurate for rooms with high average absorption, where Sabine is known to be less accurate.

Documentation note: only sabine_absorption() drives the actual treatment recommendation math; Eyring only appears as a secondary comparison metric (compare_absorption_models) in the /treatment response.

4.4 acoustic_targets.json — the standards-referenced config file

A data file, not code — it's what makes the treatment recommendations trustworthy rather than arbitrary. Two top-level sections:

room_types — 9 room categories, each with a target_rt60_seconds, an acceptable_range_seconds, and a source citation. Example: classroom targets 0.6 s, sourced from ANSI/ASA S12.60-2010 — the US school-acoustics design standard.

materials — 4 materials (acoustic_panel, bass_trap, heavy_curtain, carpet_rug), each with a per-octave-band absorption coefficient, sourced from a published ASTM C423 reverberation-room-method test-data table.

bass_trap has a much higher 125 Hz coefficient (0.35) than acoustic_panel (0.15) — the physical reason bass traps are a distinct, thicker product: low frequencies are inherently harder to absorb.

4.5 app.py — the Flask routes

Every route follows the same shape: parse the uploaded audio → run DSP functions → catch AudioLoadError (→ HTTP 400, bad input) and ValueError (→ HTTP 422, the math couldn't produce a valid result) → return JSON.

  • get_uploaded_audio() — shared helper: pulls the audio field out of request.files, validates a file was attached, calls load_audio().
  • /upload — returns the waveform for the UI to draw. No acoustic analysis yet.
  • /energydecay — runs onset extraction + energy_decay().
  • /octavebands — extracts impulse response, filters into all 6 bands, computes a decay curve per band (silently skips a band if its RT60 fit fails).
  • /fft — runs get_fft() on the raw signal (not onset-trimmed — a full spectrum view doesn't need onset alignment).
  • /RT60 — the headline endpoint: fits both T20 and T30, returns both plus R² values and a lundeby_corrected: True flag.
  • /clarity — computes C50, C80, D50.
  • /treatment — the biggest route: parses volume/room type, computes per-band T20 RT60, bass/treble ratio, surface area + Sabine-vs-Eyring comparison, broadband decay/RT60/clarity for the summary chart, and finally calls recommend_treatment() for the area-needed numbers. Merges everything into one JSON payload.
  • /roommodes — parses dimensions, calls calculate_room_modes().
  • /waterfall — calls calculate_waterfall().

CORS is configured (flask_cors) to allow the Vercel-deployed frontend (plus local dev ports) to call this API cross-origin, since frontend and backend are two separate deployed services.

5.3 WaterfallPlot3D.jsx — the 3D visualization

Renders the waterfall data as a hand-rolled 3D engine in pure SVG — no Three.js or WebGL. Key ideas:

  • project(wx, wy, wz) implements a manual orthographic 3D-to-2D projection: center the point, rotate around Y (azimuth/orbit), rotate around X (elevation/tilt), then use (x, y) as screen coordinates while keeping z (depth) for sorting.
  • Mouse/touch drag handlers update azimuth/elevation state, re-running the projection — this is how "orbit to rotate" works with plain SVG.
  • Bands are depth-sorted before rendering, painting farthest-first (a manual painter's algorithm).
  • Two render modes: Ribbons (filled gradient curtains) and Wireframe (glowing ridge lines + cross-rib mesh).

6 — Glossary

TermMeaning
RT60Time for sound energy in a room to decay by 60 dB after the source stops
T20 / T30RT60 estimated by extrapolating a 20 dB / 30 dB decay segment up to 60 dB
Impulse responseA room's acoustic "fingerprint" — its output when excited by a very short, sharp sound
Schroeder (backward) integrationReverse-time cumulative integral of squared impulse response → smooth decay curve
Lundeby's methodISO-standard iterative noise-floor estimation & correction, applied before Schroeder integration
Noise floorThe background/ambient noise level a recording never decays below
Octave bandA frequency band from center/√2 to center·√2
Nyquist frequencyHalf the sample rate — the highest frequency a digital signal can represent
Butterworth filterA filter type chosen for a maximally flat frequency response in its passband
Zero-phase filteringFiltering forward then backward to cancel phase delay/time-smearing
Room modeA standing-wave resonance formed between reflective parallel surfaces at specific frequencies
Axial / Tangential / ObliqueMode types by how many surfaces (2 / 4 / 6) they involve, and how strong they are
Schroeder frequency (f_s)Cutoff above which individual room modes overlap into a statistically diffuse field
FFTFast Fourier Transform — converts a time-domain signal into its frequency-domain magnitude spectrum
C50 / C80Early-to-late energy ratio (dB), 50ms cutoff for speech / 80ms cutoff for music — "clarity"
D50 (Definition)Early energy as a percent of total energy — a speech-intelligibility metric
Sabine equationRT60 = 0.161·V/A — links reverberation time, room volume, and total absorption
SabinUnit of absorption; 1 sabin = 1 m² of a perfectly absorptive ("open window") surface
Absorption coefficient (α)0–1 value describing what fraction of sound energy a material absorbs at a given frequency
Eyring equationAn alternative to Sabine, generally more accurate for highly absorptive rooms
Bass Ratio / Treble RatioRatios comparing low-band or high-band RT60 to mid-band RT60 — describes tonal "warmth"/"brightness"
ISO 3382-1The international standard defining how room acoustic parameters are measured and reported
ANSI/ASA S12.60The US standard setting maximum permissible classroom RT60 for speech intelligibility
R² (r-squared)Regression fit quality (0–1); how well the decay curve follows a straight line over the fitted range
Diffuse fieldAn idealized sound field where energy is statistically even in all directions
MediaRecorder APIBrowser API used to record live microphone audio (outputs WebM/Opus by default)
